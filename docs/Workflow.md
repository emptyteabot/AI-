# 评测工作流与演示说明

## 交付边界

当前提供可运行平台、32条基础与扩展任务、72条人工演示样例，以及4道独立的精简实测题。实测通过 OriginCoder 第三方网关对4个模型通道共完成16次生成和14条有效模型裁判，另有2条裁判空响应。尚无学科教师独立盲评数据，模型身份无法独立核验；演示样例和小样本实测均不足以支持全面排名。

## 任务设计

以教师在真实工作中要交付的内容为单位：40分钟教案、6页课件脚本、3道分层练习、3部分纠错反馈。每条任务指定学科、年级、难度、输出约束与参考要点。题集不是网上题目的拼接，含安全、隐私、提示注入和事实边界的原创合成任务。

统一JSON协议使格式、数量、时长等硬约束可以程序化检查；教学有效性不压缩成关键词命中。参考要点需要学科教师复核，不能称为已认证金标。

## 从一次试跑到正式比较

1. 对三个默认厂商分别发出最小连接测试，记录实际model与usage。
2. 先挑3道题，确认输出协议、Token预算和裁判JSON有效性。修复后冻结Prompt与参数。
3. 选择24条基础题时为24×3=72个生成任务；选择全部32条时为32×3=96个生成任务。启用跨厂商裁判时至多增加相同数量的计划调用。并发3，不使用无限重试。
4. 检查失败、截断和格式异常；不把HTTP失败当作内容零分，不删除不利结果。
5. 教师进入独立盲评页，对同一Query下的A/B回答独立评分。至少两名教师覆盖相同题目，保留理由并讨论分歧。
6. 查看分任务表现、规则全通过率、裁判分、人工偏好和机人一致率；报告保留样本量、缺失和不确定性。
7. 对模型结论做人工解释。发现题目或参考要点问题时创建新版本并新建实验，保留旧实验快照。

## 正式实验还需补齐

- 更大规模复测前确认各模型分组的密钥、额度、Model ID 和账单。
- 教师对参考要点、适龄性与评分锚点的复核。
- 足够的独立人工评分。浏览器会话不是可信的人员身份。
- 每Query每模型至少3次采样；按Query配对的统计分析与bootstrap区间。
- 对裁判差异进行校准。当前使用跨厂商裁判避免自评，但裁判本身不相同。
- 多模态/PPTX成品课件、真实课堂可用性验证。这些不在当前文本Demo已完成范围内。

## 5分钟现场演示顺序

- 0:00-0:40：打开概览，说明演示/真实数据标签及四类任务。
- 0:40-1:30：打开“概率中的独立性”或“隐私敏感的学情反馈”，展示Query、参考要点和硬约束。
- 1:30-2:30：新建演示实验，观察三通道调度、进度和异常保留；说明真实模式只更换数据来源，评分与存储流程相同。
- 2:30-3:30：打开原始回答与机评证据，区分格式检查、知识点提及和教学质量。
- 3:30-4:20：进入独立盲评页，解释A/B随机、五维评分、偏好、理由与防重复。
- 4:20-5:00：查看报告并导出，解释当前结论的限制；展示模型接入、费用配置和CLI自动运行方式。

## 建议的结论表达

演示阶段：“平台已打通任务定义、自动评分、匿名评审与报告导出；72条人工样例用于验证流程。另有4道题的真实网关实测，结果范围有限且模型来源由网关标识。”

真实阶段：“在固定版本的任务、指定模型与参数下得到本次结果。失败和截断已单列，人工样本数为实际完成数；结论限于本任务集，不能推广为全面模型排名。”
