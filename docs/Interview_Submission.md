# 教育场景大模型自动化评测中台：项目说明与评测报告

> **提交状态：可运行 Demo、评测方法与一组真实 API 实测已完成。** 真实实验使用 OriginCoder 第三方网关，12 道精简题 × 4 个模型通道，48 条计划生成、45 条成功、3 条失败；28 条裁判评分有效、16 条裁判失败、1 条截断未裁判。模型身份由平台标识，无法独立核验。尚无教师实际盲评；另有 72 条人工编写的演示样例，不代表真实模型。

## 一、项目目标与交付

围绕教师备课、课件脚本、习题和学习反馈四类任务，构建可重复的评测流程，回答三个问题：模型能否满足明确约束、输出是否具有教学价值、教师实际更偏好哪份回答。

交付包括：

1. 可运行的全栈中台：任务集、实验管理、六个模型通道（实验可选择至少三家）、规则机评、可选模型裁判、人工匿名盲评与可追溯报告。
2. 44 条原创合成 Query：24 条基础任务、8 条独立版本扩展任务和 12 条低预算实测短题；扩展覆盖项目式学习、苏格拉底式追问、实验诚信、凸透镜焦点边界等。
3. 演示数据、评分明细与报告：基础 24 题 × 3 个通道，保留 72 条明确标注的非模型样例；另含 12 题 × 4 通道的真实网关响应与机评记录。
4. 交互课件检查页：对自编正常与缺陷样例进行浏览器隔离预览、手动操作和简单静态线索检查。
5. 外部教师评审参考：PATS 原研究的 40 组模拟教学对话、120 条真实教师成对判断，五维数据可逐对查看、下载与复核；它是独立数据，不是对本项目回答的教师评价。

## 二、任务集设计

| 场景 | 基础 / 扩展 | 代表任务 | 核心观察点 |
|---|---:|---|---|
| 教案写作 | 6 / 2 | 异分母分数、函数单调性、雨水花园启动课 | 环节与时长、学段适配、全称命题、可操作的教学活动 |
| 课件脚本 | 6 / 2 | 三角形内角和、凸透镜、质量守恒 | 页面结构、知识边界、焦点与实验安全 |
| 习题生成 | 6 / 2 | 条件概率、史料视角、英语纠错 | 答案与解析、条件、证据和分层评价 |
| 作业反馈 | 6 / 2 | 错因诊断、启发式答疑、数据诚信 | 不羞辱学生、不给出原题完整答案、诚实记录 |

基础集 `edu-core-v1.0` 有基础、进阶、挑战各 8 条；扩展集 `edu-extension-v1.0` 有进阶 2 条、挑战 6 条。参考要点是任务设计者的评审辅助信息，未经过学科专家系统标定。历史实验固定题目快照和 SHA-256，后续扩展不改写旧实验。

**Query 示例：启发式追问。** 学生对一元二次方程 `(k-1)x²+2x-1=0` 的错解只检查判别式并得到 `k>0`。要求模型提出三轮问题，引导学生检查一元二次方程的前提，学生可见内容不能直接给出原题完整范围。评审参考答案是 `k>0 且 k≠1`。系统对部分直接条件或完整答案表达设置零权重泄露提示；同义改写和暗示仍须人工判断。

**Query 示例：凸透镜。** 焦距固定为 10 cm，要求课件脚本比较物距 25、20、15、10、6 cm，解释焦点处无有限距离实像，并讨论遮挡部分透镜后的像。模型评测输出是结构化文字脚本；课件检查页的 HTML 是另行编写的演示，不能说成模型生成结果。

## 三、评分与盲评

### 规则机评（edu-rubric-v1.1）

| 检查 | 权重 | 能回答的问题 |
|---|---:|---|
| 严格 JSON 与字段类型 | 15 | 结果能否被约定程序解析 |
| 内容数量与教案时长 | 25 | 是否满足数量和时间硬约束 |
| 教学目标与分层支持 | 15 | 是否提供基本目标与分层内容 |
| 检测题与解析 | 20 | 数量和必要字段是否完整 |
| 参考概念提及 | 15 | 是否出现设定的关键词组 |
| 安全说明与手机号模式 | 10 | 是否提供安全说明并触发简单隐私扫描 |

v1.1 在原有权重上增加启发式答案泄露线索；旧实验保留原有评分版本。规则分是以上检查权重之和。关键词命中不证明事实正确；字段存在不证明教学安全。启发式答疑另有不改变分数的泄露线索，命中时整条任务标记未全部通过；未命中仍需人工复核。

### 模型裁判与人工评分

同一份五维量表：知识准确性 30%、教学适切性 25%、指令遵循 20%、表达结构 15%、教育安全 10%。每项 1–5 分，按 `(分数 - 1) / 4` 归一化后加权映射到 0–100。模型裁判要求引用可核对的文本证据，不要求输出隐含思维链；若裁判结果无效或截断则保留错误，不编造分数。

可选模型裁判使用不同于生成方的一家已选厂商；**当前每条回答只有一名模型裁判，不是双裁判或 A/B 位置交换机评**。不同生成方可能对应不同裁判，因此仍有裁判异质性。

盲评服务端按题目随机分配匿名 A/B，隐藏接口记录中的厂商、耗时和机评分；评审需填写两份五维评分、偏好及理由。内容本身可能自报身份，且公开实验原始数据可按文本反查来源，属于流程性盲评，不防恶意反查。浏览器会话去重不等于真实人员身份验证；当前没有企业级评审权限隔离，也不宣称已经完成教师双盲标注。

外部教师参考集来自 PATS（Rooein 等，EACL 2026）：4 名教师对 40 个模型模拟的教学对话对分别评价 3 次，共 120 条记录、600 个维度选择。原结果为成对偏好或平局，与本项目五维 1–5 量表不同。其角色格式和 A/B 顺序在导入时归一，保留源 ID、原始顺序与 SHA-256，详见 `docs/Teacher_Data.md`。原数据仓库许可 MIT，对话按原论文为 CC BY 4.0；原图未包含在子集中。

## 四、已完成的演示结果

固定基础集和默认参数，运行 24 题 × 3 个通道的样例流程：**72/72 成功，0 失败，39 条命中人工复核条件**。三通道样例由程序按通道故意植入不同缺陷；样例分数仅用于验证展示与汇总，不代表真实模型。

基线演示未启用模型裁判、没有教师盲评、真实 Token、延迟与费用。另有一次浏览器表单验收投票，仅验证流程，不是教研评价。原始样例及规则证据见 `docs/evidence/`。

## 五、真实实测及进一步评测方案

实测 12 条合成教育题覆盖教案、课件脚本、习题和反馈，来自 `edu-mini-v1.0`。OriginCoder 标识的 DeepSeek、OpenAI、xAI、Anthropic 四个通道计划各生成 12 条，实际分别成功 9、12、12、12 条。规则均分依次为 81.7、86.3、98.8、69.2；模型裁判均分分别为 88.4（n=6）、86.1（n=7）、82.1（n=8）和 73.8（n=7）。另有 16 条裁判失败、1 条截断未裁判、3 条生成失败；裁判异质性和缺失使得均分不可直接视为公平排名。扩展阶段先并发 6，续跑与补试并发 2，4 条 502/503 各补试一次，首次错误留存。MINI-003 的参考要点包含题目未要求的估算，部分裁判据此扣分；MINI-011 某次裁判误判检测题数量，规则却正确识别。MINI-004 中两个通道输出了两道而非一道检测题，另一个通道的 JSON 内部引号未转义。完整实验快照见 `lib/eval/public-real-eval.json`。

以下为扩大样本时的计划：

1. 在“模型接入”配置至少三家模型来源的有效 API Key（可选 B.AI、硅基流动统一托管，或分别使用官方接口），先用每家一次连接测试核对模型 ID、地域与权限。价格由操作者按实际计费信息填写，缺失时费用显示未知。
2. 先跑 3 题 × 3 家的试运行，检查格式、错误、截断、原始响应和计费；再按需求选择 24 条基础题或 32 条完整题集。
3. 完整题集单次采样是 **32 × 3 = 96 次计划生成调用**；启用模型裁判最多再产生 96 次计划调用。网络/限流重试可能增加实际调用，`--max-calls` 限制计划调用数而非金额。
4. 至少邀请两名具备相关学科经验的评审员独立标注，记录覆盖率、分歧、评分锚点和复核流程；当前 Demo 的会话机制需要配合线下身份管理。
5. 按任务和模型报告成功率、截断、规则分、裁判分、人工偏好及样本量；对同一 Query 的模型差异做配对分析，必要时扩充题目和重复采样。小样本 Wilson 区间只作描述，不等同于严格的聚类推断。
6. 保存原始响应、运行参数、版本和实际 usage；账单与发票从真实付费账号取得，平台导出的估算不替代财务票据。

## 六、演示顺序与架构

1. 进入“任务与 Benchmark”，展示 24 条基础题、8 条扩展题及 12 条精简实测题，并打开启发式追问。
2. 进入“课件检查”，先在正常样例将物距调到 10 cm，再切换故意缺陷样例观察 `Infinity`；这只是两个自编样例的手动检查。
3. 在“评测实验”运行演示模式；查看规则问题和 72 条基础样例。真实模式需自行配置模型 API Key。
4. 进入独立“人工盲评”，完成匿名 A/B 的评分和理由；回到报告页查看结果与导出。

前端为 React / TypeScript；服务端通过 API 路由、持久化队列和 SQLite 存储题目、实验、结果和盲评。配置和题目在实验时冻结；失败不按零分混入质量均值，截断不进入裁判均值。

本地启动：

```bash
npx pnpm@11.25.0 install --frozen-lockfile
npm run setup:local
npm run dev
```

打开 `http://localhost:5173`；独立盲评为 `/review`。浏览器调度依赖页面保持打开，CLI 可在本地服务启动后运行 `npm run eval -- --url http://localhost:5173`。详情见 README。

## 七、验证、局限与材料取舍

- 自动测试覆盖任务平衡、规则边界、厂商请求构造、失败处理、盲评字段隔离、扩展题和部分答案泄露检测。
- 已在浏览器中完成基础演示实验和一组测试盲评；新增课件样例在焦点处分别观察到正常提示与故意缺陷样例的 `Infinity`。
- 已提供[免登录静态备用站](https://lessonbench-80b5043b86.deed.page/)、完整在线工作台与自有服务器运行方案。2026-10-29 多地 HTTP 拨测时备用站多数节点返回 200，完整工作台多数大陆节点返回 403；不同网络的实际可达性不保证。浏览器工作区和分享链接通过本地隔离测试；第三方网关真实 API 已调用，但模型实际身份、教师金标和多评审员身份认证尚未核实。
- HTML 预览使用 iframe 沙箱和内容安全策略，但不等于适合运行任意恶意代码的完整隔离环境。没有实现无头 Chromium 自动轨迹、视觉模型裁判或自动修复，不能宣称这些能力已上线。
- 已有小样本原始调用和机评记录，但不足以支持全面排名、人工胜率或机人相关系数。费用和发票以实际账单为准。
